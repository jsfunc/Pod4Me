# Pod4Me

A local Android podcast manager for a Galaxy S24 and newer phones. Native Kotlin / Jetpack Compose UI, SQLite storage, Android DownloadManager downloads, and Media3 background playback. No accounts, analytics, or application server.

**The independent web app for iPhone and laptops is at [Pod4Me web](https://pod4me.aurelien-garivier.workers.dev/app/).** It supports subscriptions, feed-list import/export, episode browsing, streaming, sharing, queues, lists, stars and bookmarks. Android and web exchange feed lists and recommendation links; they do not synchronize automatically. **Updated deployment verified on 2026-11-01:** Discover now calls Apple directly, Refresh preserves unsubscribe status, feed compatibility is improved, and playback saves avoid rewriting the whole library. The live HTML and JavaScript match the prepared update. Future deployments use `dist/Pod4Me-web.zip` and `dist/Pod4Me-web/README.txt`; see [web features and checks](docs/web-app.md).

For future development, start with [AGENTS.md](AGENTS.md) and the [development handover](docs/handover.md), which record the accepted requirements, current state, build/signing workflow and pending checks.

## Build an installable APK

On Ubuntu, from a normal terminal with internet access:

```bash
sudo apt-get update
sudo apt-get install -y openjdk-17-jdk curl unzip
cd /home/aurelien/repo/Pod4Me
./tools/setup-android.sh
./tools/build-apk.sh
```

Review and accept the Android SDK licenses when prompted. The setup script installs command-line tools, SDK platform 36, build tools 35.0.0, and platform-tools in `~/Android/Sdk`. Gradle and dependencies are cached in `~/.gradle`; both locations are shared with future projects. Set `ANDROID_HOME` or `GRADLE_USER_HOME` to override them. A full JDK 17 is required; a Java runtime without compiler tools is insufficient.

The build script runs core/schema checks, Android unit tests, release lint, release assembly and compilation of device tests. It produces a signed, non-debuggable **`dist/Pod4Me.apk`**, `dist/Pod4Me-1.0.22.apk`, and SHA-256 checksums. The APK supports Android 14+ (minimum API 34, compile/target API 36), including Android 17. Compatibility with the specific One UI 9 device still needs testing.

Transfer the APK to the phone and open it, allowing installation from the app used to open the file. For existing local installs, the script copies `~/.android/debug.keystore` once to the dedicated `~/.android/pod4me-v1.keystore`. Updates preserve data when this key matches the installed APK. On another computer, copy the existing personal keystore privately instead of adopting that computer’s debug key. The release APK is **not debuggable**, even though its certificate is retained from earlier builds. Keep a private backup of that keystore. The script also compares the certificate with an existing `dist/Pod4Me.apk` and stops on mismatch.

To use an existing personal keystore instead, set `POD4ME_KEYSTORE`, `POD4ME_STORE_PASSWORD`, `POD4ME_KEY_ALIAS` and `POD4ME_KEY_PASSWORD`. Its certificate must match the installed app to update it. Changing certificates is a separate migration; do not uninstall your current app to resolve a signing error.

To download directly on a phone connected to the same Wi-Fi, run `python3 tools/serve-apk.py` in your normal terminal and open the printed URL on the phone. The server exposes only APK/checksum files in `dist/`, without directory browsing or symlink access; stop it with Ctrl+C after downloading.

The GitHub Actions workflow `.github/workflows/android.yml` runs debug checks, release lint and compilation of device tests, and uploads a `Pod4Me-APK` artifact containing the installable debug APK. It does not publish a public release. GitHub artifacts are ZIP files: download and extract the APK before installing. Each fresh runner may use a different debug signing key. Use CI artifacts for build checking; the local release script with the existing personal key is the supported update path.

To expose Android tools to other projects, add this once to `~/.bashrc`:

```bash
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export ANDROID_HOME="$HOME/Android/Sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"
```

Explicitly choosing an unplayable episode reports failure and stops. Video streaming supports HTTP/HTTPS redirects. Rotation connects the controller before maintenance and avoids repeating launch work; normal foreground returns still reconcile downloads and expiry. Radio preference recovery keeps valid entries and preserves the original damaged list.

Removing a queue entry keeps its audio. When empty, playback follows the source list order captured when Play was pressed. Previous/Next and headphone controls use the actual player timeline. Starting in the middle includes up to five preceding downloaded episodes. Restored queue entries with missing audio offer a download button and are skipped until downloaded.
- **Sleep timer:** the Player clock opens a 1–120 minute slider (default 15) or End of episode. While running it shows a countdown; tap to change/cancel. The service timer continues through background playback, pauses and track changes. Expiry pauses podcasts with saved position, or stops radio and clears its buffer. End mode prevents the next queued episode from starting. Stop cancels the timer.
- **Fullscreen video:** enter only with the fullscreen button. Rotation fits the whole picture without entering/exiting fullscreen or restarting playback. Tap to reveal controls; they hide while playing, except with TalkBack. Back/close returns to Player.
- **Player:** background playback, position scrubbing, a single row of playback controls, ±10 seconds, previous/next, global speed from 1.0× to 3.0×, and optionally named bookmarks. Playback positions persist periodically and on pause/seek/track changes.

Bottom navigation uses six equally sized icon-only buttons, including a radio-antenna symbol for Live; their names remain available to accessibility services. Feeds uses a dedicated microphone icon without launcher padding so it appears comparable in size to the others. Library keeps its compact cards and 40 dp artwork.

Feed artwork appears next to feeds and episodes in Feeds, Library, Queue, Latest, and the player. RSS images, iTunes artwork, and Atom logos/icons are supported. Press **Refresh** after upgrading to retrieve artwork for existing feeds. Images are cached; feeds with missing or unavailable artwork display a podcast symbol. Database migrations preserve existing library data.

To unsubscribe, tap the **bin in the feed's row** and confirm. This removes the subscription from Feeds, Latest, refresh and export. Existing downloads, pending manual downloads, queued episodes, ratings, bookmarks, feed settings and list memberships remain. Re-adding or importing the URL restores the subscription using its existing data. The version 2-to-3 database migration preserves current subscriptions and episode data.

RSS/Atom responses are parsed incrementally, with a 64 MB limit on the uncompressed response and a three-minute request timeout. The parser retains episode metadata without buffering the whole response or constructing a DOM tree. Feeds larger than the former 8 MB limit are supported; feeds above 64 MB still report a size-limit error. XML DTDs (including harmless DOCTYPE declarations) and external entities are rejected. RSS 1.0/RDF is unsupported. Direct audio/video enclosures are supported; Media RSS audio/video is accepted when no usable normal enclosure exists. Titles are capped at 4,096 characters and descriptions at 1,048,576 during parsing; unusually long content is visibly shortened. Identifiers are never silently truncated. Unsupported or invalid enclosures produce a skipped-episode count on the feed. RFC publication dates with US zone abbreviations, French month forms and two-digit years (1970–2069) are supported; dates without a timezone and date-only values use UTC. Declared durations longer than seven days are treated as unknown until measured by the player.

Episode metadata is retained even when an item disappears from a rolling feed. History is not automatically pruned. Show notes load only when Details is opened; periodic playback saves update one episode without reloading notes. Unchanged episode metadata is not rewritten on refresh.

## Discover podcasts

In Feeds, tap **Suggest** immediately after Export. Pod4Me selects up to ten suggestions when requested: normally seven related-search results and three popular shows, filling remaining slots from either source. Search terms come from a rotating sample of subscribed feed names, repeated recent episode-title topics, and positively rated suggestion topics. Up to three searches balance those interests with exploration. Apple’s country chart uses the phone’s region (US fallback). This is keyword-based discovery, not an AI or listening-history recommendation service; language matching is not guaranteed. Each suggestion shows its publisher and why it was selected, plus **Subscribe** and an **Apple Podcasts** link. Subscribe is explicit and downloads no audio automatically.

Every suggestion has thumbs-up and thumbs-down buttons. A selected thumb is highlighted; tap it again to clear the rating, or tap the other thumb to change it. Ratings favor or lower the priority of matching titles, directory topics and publishers, and influence search terms. A thumbs-down does not permanently ban a show. Ratings are separate from episode stars.

Already subscribed feeds, duplicate feed URLs and every item in the previous successful suggestion batch are excluded. Older suggestions are allowed to return, but the most recent 100 are ranked lower to favor variety. The previous batch and ratings survive app restarts. If no fresh candidates are available, the app says so instead of repeating the previous batch; failures and empty results do not erase that history. There may be fewer than ten when the directory has too few usable results or requests fail. Apple receives search terms (which can reflect liked topics) and the region; the full library, individual thumb ratings, notes and playback history are not uploaded. Ratings and suggestion history are saved only on this phone, survive app updates, and are currently excluded from portable library backups. Clearing app data or uninstalling removes them. Calls use public endpoints without an account, API key or paid API plan. Only text metadata and links are displayed; Apple promotional artwork/audio is not copied. Requests are spaced at least 3.1 seconds apart and directory responses are cached in memory for ten minutes (up to 40 requests); selection is recomputed on every tap. There is no automatic discovery job. See [Apple’s Search API documentation](https://performance-partners.apple.com/search-api).

Scroll memory covers navigation, rotation and Android saved-state restoration. Re-selecting Latest returns to its current feed/search; use All feeds to return to the global list. Each Library filter/sort and feed search has its own position. Saved list anchors follow the same item when possible, with a nearby-position fallback when it disappears. Refresh highlights are stored locally but excluded from portable backups; existing local highlights survive a merge restore, and newly restored episodes start unhighlighted. Scroll memory and discovery caches are UI state, not part of library backups; a fresh launch without Android-restored state starts a new UI session.

## Portable library backup

In **Feeds**, use **Back up library** to save a versioned JSON file through Android's document picker. This is separate from **Export**, which exports subscription addresses as text or OPML. Library backups include subscriptions, custom names and expiry settings, episode metadata and notes, lists/memberships, ratings, progress, bookmarks, queue, global speed and saved playback context. Audio files, local paths, Android download IDs and live-radio subscriptions are excluded. Automatic cloud and device-transfer backup remain disabled.

Stop playback, choose **Restore library**, select the JSON file and confirm. Restore merges by feed URL, episode GUID and list name. Backup feed settings, ratings and progress replace matching values; memberships are combined, bookmarks are deduplicated, and restored queue entries append without duplicates. Existing audio and downloads remain. On another phone, missing audio must be downloaded manually. Queue entries remain available for downloading even if their feeds are unsubscribed. Invalid backups roll back the entire database change. Maximum backup input is 256 MB, with bounded record and field sizes.

## Storage rules

Heard/Unheard applies only to downloaded episodes. Each Library list/feed has a Delete all downloads button with confirmation. It preserves 4ever/current playback, rechecks protection and membership, and removes the same files from every list and Queue while keeping metadata, history, ratings and bookmarks. No Hide Heard toggle is added.

New downloads expire after 30 days unless their feed specifies a different period or infinity. Expiry is checked when the activity enters the foreground, not by a background timer. At 95% playback, an episode becomes Heard and its expiry becomes the earlier of its existing deadline and three days from that moment. Seeking past the threshold counts as reaching it. Removing an episode from Unheard also marks it heard; marking it Unheard resets its saved position.

An episode in **4ever** cannot be deleted manually or by expiry until removed from that list. Playing, buffering and paused current playback are protected too; stop it before deleting. Opening a cold session does not load the previous episode or protect it from expiry; headset resumption loads it when requested. If no track is loaded, Play selects the first playable queued episode, then falls back to the saved episode. If neither is available, it explains how to download/select audio. Deleting audio retains ratings, bookmarks, list memberships, and playback history. A successful re-download becomes Unheard at position zero with the feed’s normal download expiry; failed/cancelled downloads do not reset history.

Unheard and Heard are derived views and are mutually exclusive. Each feed has an automatic view. Custom lists support create/rename/delete and many-to-many episode membership. Deleting a custom list does not delete audio. Default feed-list changes and expiry settings apply to future downloads.

## Code organization

- `domain/`: immutable UI models, sorting, expiry/protection rules, RSS/Atom parsing, suggestions, and queue ordering.
- `data/`: serialized SQLite transactions, feed fetching, durable OS downloads, cleanup, and completion reconciliation. Schema changes require an explicit migration; there is no destructive upgrade fallback.
- `playback/`: MediaSessionService owns ExoPlayer; the UI uses a MediaController. No activity owns the audio player.
- `ui/`: lifecycle-aware state and Compose screens.

Implementation references: [Media3 background playback](https://developer.android.com/media/media3/session/background-playback), [connecting a controller](https://developer.android.com/media/media3/session/connect-to-media-app), and [AGP 8.13 compatibility](https://developer.android.com/build/releases/agp-8-13-0-release-notes).
