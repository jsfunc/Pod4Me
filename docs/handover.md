  - **Sleep timer:** compact Player clock button; 1–120 minute slider, one-minute steps, default **15 minutes**, plus End of episode for podcasts. A countdown replaces the clock, with change/cancel controls. The playback service owns an elapsed-time deadline and one cancellable expiry job; the UI calculates the countdown from a deadline published once, without per-second session broadcasts. A Play request after sleeping past an expired paused timer clears that stale timer and resumes normally. During background playback, manual pauses/track changes do not reset it. Expiry pauses podcasts and saves position; radio stops capture and clears the buffer. End mode sets Media3 pause-at-end so the next queued episode does not start. Stop cancels; switching to radio cancels End mode. No fades or shake. Phone screen-off/end-of-queue acceptance is pending.
  - **Name search:** the existing + dialog accepts a name, RSS/Atom URL, Apple podcast URL or YouTube channel URL. Names use Apple's directory, compact artwork/title/publisher/icon rows and + changing to a subscribed check. No automatic downloads; audio/video remain separate. Search on YouTube opens external search, then share/paste the chosen channel back. **Directory limitation verified live:** Apple supplies public RSS URLs for Transfert and The Daily, but omitted them for the tested France Culture results, including lookup. Only results with a usable RSS address are offered; paste the publisher's RSS URL for missing shows. No scraping or fabricated RSS addresses.
  - **Refresh:** manual metadata only, excluding YouTube; four concurrent fetches, ETag/Last-Modified conditional requests, progress in the existing header, silent success and failed-feed summary with Retry failed feeds. A successful 304 clears old new-episode highlights; failures retain them. Preserve custom names/history. Persist permanent redirect prefixes and validated iTunes new-feed-url, but never persist HTTPS→HTTP moves (use the response while retaining the secure address). Conflicts with an active subscription require review. **User decision for a previously unsubscribed destination:** retain the current subscription address and refresh normally, preserving both histories separately, without merging or resubscribing the old destination. In-flight results cannot resubscribe or overwrite a changed address.
  - **Backlog:** Heard/Unheard only applies to downloaded episodes. Successful re-download becomes Unheard and resets position to zero; failed/cancelled downloads preserve history. Ratings/bookmarks/list memberships survive. **User decision after N8:** marking Unheard keeps the shortened Heard expiry; it resets position but never restores or extends the deadline. No Hide Heard or bulk marking older episodes.
  - **Delete all downloads:** compact bin beside the Downloads heading, acting on the selected list/feed. Confirm list name/count and cross-list file availability. Snapshot only eligible IDs; recheck list membership, 4ever and active playback at execution, report skips/failures. Keep list/metadata/history; remove corresponding queue entries. New downloads made after confirmation are not included.
  - **Heard retention:** three days after becoming Heard, never extending an earlier deadline. Schema **8** explicitly adds feed validators/last-refresh time and caps existing downloaded Heard deadlines at upgrade time +3 days, retaining earlier deadlines. The old schema has no Heard timestamp, so the upgrade cannot reconstruct the original transition time. 4ever/current-playback deletion protection remains. Backup format stays **2**; refresh validators/times are not portable user state.

## Accepted product behavior

### Feeds, import, sharing and history

- Subscribe by RSS/Atom URL; feed names are customizable and refresh preserves custom names/settings.
- Refresh is manual, using a button. Successful refresh produces no confirmation popup; failures remain visible. Downloads are manual and may use mobile data; roaming is disabled. No automatic refresh/download scheduler.
- Feed export is UTF-8 text, one **`url [podcast title]`** per line. Import reads only the URL before the first whitespace, ignoring all trailing text. Plain URLs, BOM, CRLF and Unicode whitespace are supported; encoded `%20` remains part of a URL. Limit: 1 MiB / 1,000 URLs per import.
- Unsubscribe is confirmed via the feed bin icon. It hides the subscription from Feeds, Latest, refresh and feed export while retaining downloads, pending downloads, queue, feed settings, ratings, bookmarks, lists and history. Resubscribing the same URL restores that feed's identity and data. An in-flight refresh must not resubscribe it.
- Share in track Info, feed cards and feed settings opens Suggest / Copy URL. Copy URL copies the direct audio URL for a track or RSS URL for a feed. Suggest uses Android sharing apps and a single HTTPS Pod4Me recommendation link carrying the URL/type/title/source-feed metadata. The Cloudflare page is static, with no accounts or messaging backend; old custom links still parse. Incoming ACTION_SEND/App Links/custom links require confirmation before subscribing/downloading; feed suggestions need one Subscribe action after opening in Pod4Me. Ordinary episode webpages are not resolved into audio URLs.
- Shared audio reuses an exact existing audio URL match; unmatched audio remains in Shared episodes even when Also subscribe adds its source podcast. Shared standalone audio belongs to pseudo-feed **ID `shared`, URL empty**. It is excluded from feed URL export. Restoring it onto an empty library must retain ID `shared`; later shared downloads otherwise fail foreign-key checks.
- In-feed search covers all locally stored metadata for the selected feed, regardless of audio availability. Refresh remains manual. Search ranks exact title matches above weaker partial/typo matches, ignores case/accents, requires each query word in either title or description, and allows arbitrary word order. Partial matching starts at three characters, typo matching at four (one insertion/deletion/replacement/adjacent swap). Synonyms are not included.
- Rolling feed history is deliberately retained. No automatic metadata pruning. Starred includes rated episodes whose audio is missing/expired so they can be downloaded again. Changing sort while in Starred stays in Starred.

### Lists, expiry and playback

The following describes **1.0.22** behaviour; the feature round above records its implementation details and pending phone checks.

- Permanent system lists: Unheard, Heard, 4ever. Custom lists can be created, renamed and deleted. Episodes can belong to several lists; each feed also has an automatic view and configurable default lists for future downloads.
- Default expiry is **30 days**, configurable per feed from 1–36,500 days or forever. Expiry deletion is checked on foreground launch, not by a timer.
- Heard begins at **95%**; seeking past the threshold counts. Its expiry becomes the earlier of its previous deadline and three days from being marked heard (downloaded episodes only). Repeated saves do not extend that deadline.
- Removing Unheard marks Heard. Marking Unheard resets position to zero, including seeking the current player to zero, and intentionally keeps the existing shortened expiry (user confirmed after review N8). A successful re-download becomes **Unheard at position zero**; failed/cancelled downloads preserve history. Ratings, bookmarks and other list memberships survive.
- **4ever prevents both manual and automatic audio deletion.** Playing, buffering and paused current playback are protected until Stop. A cold restored session stays unloaded so merely opening the app does not protect the old episode from deletion.
- Removing audio keeps metadata, ratings, bookmarks, list memberships and position; it removes the queue entry. Unsubscribe is different and retains the queue/audio.
- Explicit queue entries play first; when exhausted, continue in the source-list sort order captured at Play. Missing audio is skipped. Restored queue entries without files remain available for manual download. Starting in the middle seeds up to five preceding downloaded items for Previous.
- Remember position per episode; remember speed **globally only**, range 1.0–3.0. Bookmark names are optional and editable. Background playback belongs to the service, with system progress, Play/Pause, Previous/Next and ±10-second commands.
- Latest/feed Browse retain future dates and initially center the newest episode with publication time <= now (bounded by list edges), falling back to the top for all-future lists. Saved scroll positions take priority; search still opens at the best match.
- Sorts: publication date descending, download date descending, stars descending, feed name, progress ascending (0% first), with stable publication/id tie-breaks.
- Storage uses rounded integer decimal GB as requested; retain the exact header wording below rather than switching small values to MB.

Important regression traps:

- **Conditional refresh/parser changes:** when a release changes FeedParser output or introduces derived feed metadata, explicitly clear `feeds.etag` and `feeds.last_modified` in its data-preserving migration. Otherwise a quiet feed can return 304 indefinitely and never populate the new metadata. Do not clear user state/history.
- Progress saves update one lightweight episode, without rereading all notes. No-op download reconciliation does not publish a new snapshot. Refresh avoids rewriting unchanged episode metadata.
- Marking Unheard increments a per-episode progress epoch. Player callbacks capture epochs when scheduling saves; stale pre-reset writes are ignored. Route current-item reset through the service. Same-item seeks save only the new position; measured player duration wins over feed duration. Playlist replacement discontinuities must not save an unrelated old position/duration.
- Keep the completed Android download ID in `manager_id` until audio deletion. Calling `DownloadManager.remove()` immediately on success would delete the downloaded file. `download_id` is for pending downloads; completion broadcast plus launch/fallback reconciliation handle state changes.
- Audio files live under the app's external Podcasts directory as `<episodeId>.audio`. Deletion checks canonical parent location and current/4ever protection. Missing files are reconciled while retaining history.
- Playback preferences are in `playback`: `current`, `order` (JSON array), `cursor`, `speed`, `radio`. A cold session does not preload the saved item; media-button resumption loads it on request. External controllers cannot inject arbitrary media items.
- Schema assets use **one complete SQL statement per line**, not splitting on every semicolon. Migrations: 1→2 artwork URL; 2→3 subscribed flag; 3→4 completed manager ID; 4→5 latest-refresh episode marker; 5→6 video flag; 6→7 nullable enclosure byte size; 7→8 feed validators/refresh time and the three-day cap for existing downloaded Heard deadlines. Increment schema and test upgrade paths for future changes.

Parser limits/choices: RSS 2-style documents (including coherent default/prefixed namespaces) and Atom; 64 MiB decoded HTTP response; 3-minute HTTP call timeout. Direct audio/video enclosures are supported; Media RSS audio/video is a fallback after normal enclosures. Titles are capped at 4,096 UTF-16 characters and each description at 1,048,576, with visible shortening markers; oversized captured identifiers are rejected rather than truncated. Fixed RFC US timezone abbreviations; English/French RFC forms and two-digit years (70–99 → 1970–1999, 00–69 → 2000–2069); timezone-less/date-only dates use UTC. Unsafe HTTP credentials/schemes are rejected; illegal enclosure characters are percent-encoded while existing escapes/query semantics are preserved. Report skipped unsupported/invalid enclosures. Durations over seven days are unknown until measured. RSS 1.0/RDF and all DOCTYPE declarations remain unsupported. Video must be a direct enclosure, not a YouTube webpage/channel entry.
