Overall assessment
------------------
No HIGH finding. The dangerous surfaces — XML from arbitrary publishers, SQL, file deletion,
deep links and shared text, external media controllers, backup import, the public relay, HTML
rendering in the browser — are handled carefully and defensively on both platforms, and the
automated suites exercise exactly those surfaces. The code is small, readable and well layered.

Two items deserve action soon:

  * S1  The release certificate is a renamed Android debug key with the default alias and
        password, and the build script will mint a *new* certificate from the local debug
        keystore if the personal one is missing. This is a key-hygiene problem, not a remote
        vulnerability, but it is the one thing that could lock users out of updates or let a
        leaked file sign a malicious update.
  * B1  Web Discover is broken in production (Apple answers 429/403 to Cloudflare), confirmed
        again today. Apple's three endpoints send `Access-Control-Allow-Origin: *`, so the fix is
        to call Apple from the browser instead of through the relay.

Everything else is LOW: parser/relay edge cases that reject feeds Android (or the web) accepts,
a web refresh that silently re-subscribes, O(library) persistence on every web save, and small
Android UX corners. The largest residual risk is procedural: not a single device or real-browser
acceptance check has been completed for any version.

Severity scale: HIGH = will bite in normal use, or a real security hole; MEDIUM = incorrect
behaviour in a reachable situation, or a security weakness that needs a precondition;
LOW = robustness, consistency or quality; INFO = worth knowing, no action required.

FINDINGS
========

Security
--------

S1  MEDIUM  Release signing key is a renamed debug key with default credentials; the build
            script can silently mint a new certificate
    Where: app/build.gradle.kts:33-40 (alias "androiddebugkey", password "android" unless env
           overrides); tools/build-apk.sh:15-24 (copies ~/.android/debug.keystore to
           pod4me-v1.keystore when the personal file is absent).
    What:  Any copy of ~/.android/pod4me-v1.keystore signs updates every installed phone
           accepts, and the password protecting it is the universally known debug default. The
           project already has two live certificates (134a… here, 6585… on the other machine),
           which is exactly the failure mode the fallback produces: run the script on a new
           machine without the key and you get a third certificate and another forced reinstall.
    Why it matters: not remotely exploitable, but it is the single point that can either lock
           users out of updates (lost/duplicated key) or let a leaked file deliver a malicious
           update. The APK is publicly downloadable from ENS, so its certificate is the only
           thing that ties updates to you.
    Fix:   Keep the current certificate (changing it forces reinstall). Then: (1) remove the
           auto-copy fallback so a missing key fails with instructions instead of creating a
           new one; (2) change the keystore/key password (keytool -storepasswd / -keypasswd) and
           supply it via POD4ME_STORE_PASSWORD / POD4ME_KEY_PASSWORD, never as a default in the
           build file; (3) keep one encrypted offline backup; (4) record in docs/handover.md
           which certificate the phone actually runs (still "unverified" there).

S2  LOW     Cleartext HTTP is permitted for every host; HTTPS→HTTP redirects are followed
    Where: app/src/main/AndroidManifest.xml:12 (android:usesCleartextTraffic="true", no
           networkSecurityConfig); data/FeedClient.kt (OkHttp default followSslRedirects);
           DownloadManager requests in data/LibraryStore.kt:227.
    What:  Feeds and audio may be fetched over plain HTTP, and a feed that redirects from https
           to http is accepted. An on-path attacker on a hostile Wi-Fi can rewrite episode
           metadata or substitute audio content. Parser hardening means the impact is content
           integrity, not code execution.
    Fix:   This is a legitimate trade-off (many podcast feeds are still http://). Cheap
           improvements: try the https:// variant first when a user enters an http:// URL and
           keep https if it works; set followSslRedirects(false) and surface the downgrade as a
           feed error; show a small "insecure" marker on http feeds. The web app's relay already
           normalises this problem away for browser users.

S3  LOW     The relay is a public, unauthenticated, unrated metadata proxy
    Where: webapp/worker.mjs:61-68 (sameOrigin only applies when Origin/Sec-Fetch-Site are
           sent), 203-293.
    What:  Any script can fetch arbitrary public RSS/Atom (≤ 32 MiB) or Apple JSON (≤ 2 MiB)
           through your Worker. Worst case is exhausting the Workers Free daily request/CPU
           allowance (denial of your own service) and modest bandwidth amplification. The XML
           preamble check prevents use as a general-purpose proxy; this is documented in
           docs/web-app.md.
    Fix:   Add a Cloudflare rate-limiting rule for /api/* (one rule is included in the free
           plan), and consider requiring Sec-Fetch-Mode: cors + Sec-Fetch-Site: same-origin for
           /api/* (all browsers that can run the app send them). Keep the current fail-closed
           behaviour on errors.

S4  LOW     SSRF defence is URL-level only
    Where: webapp/worker.mjs:30-51, 74-97.
    What:  A public hostname that resolves to an internal address passes publicUrl; redirects
           are re-validated but DNS is not pinned. In practice Cloudflare refuses Worker fetches
           to private/Cloudflare-internal ranges, and the response must look like a feed to be
           returned, so exposure is minimal and already documented.
    Fix:   None required beyond keeping the documentation honest. Do not add R2/KV bindings or
           secrets to this Worker without revisiting this.

S5  LOW     serve-apk.py exposes all of dist/ with directory listings on every interface
    Where: tools/serve-apk.py:19 (bind 0.0.0.0), SimpleHTTPRequestHandler default listing.
    What:  While running, anyone on the LAN can browse dist/, which also holds the web
           deployment package, checksums and QA screenshots. No secrets are in dist/, but the
           intent is "serve the APK".
    Fix:   Serve only *.apk and *.sha256 (override list_directory to 403, or copy the APK to a
           temp dir), and/or bind to the Wi-Fi interface address that is printed.

S6  INFO    Web CSP permits http: media and https: images
    Where: webapp/public/app/index.html:8.
    What:  media-src http: is needed for publishers without HTTPS audio; browsers will block or
           auto-upgrade it as mixed content and the player shows a message. img-src https:
           lets publishers see the listener's IP (same as audio; inherent to streaming).
           Everything else in the policy is tight. No action.

S7  INFO    CI artifact is a debuggable debug APK signed with the runner's key
    Where: .github/workflows/android.yml ("Prepare APK download").
    What:  Fine for build verification, must never be distributed (README already says so).
           The workflow also runs check_schema.py without -I (harmless on a runner).

S8  INFO    Dependency currency
    What:  Lint reports 7 GradleDependency + 3 NewerVersionAvailable + 1 AGP notice. No known
           CVEs were identified in the pinned set (OkHttp 4.12.0, Media3 1.8.0, Coil 2.7.0,
           kotlinx-coroutines 1.10.2, Compose BOM 2025.10.01, Robolectric 4.16). The web app
           has zero runtime npm dependencies; Wrangler is pinned. Review quarterly.

Bugs and undesirable behaviour
------------------------------

B1  MEDIUM  Web Discover does not work in production (Apple 429/403 to Cloudflare) — and the
            relay is unnecessary for it
    Where: webapp/worker.mjs:252-278 (/api/search, /api/chart); webapp/public/app/app.mjs:97-98
           (directory(), discover()); index.html:8 (connect-src 'self').
    What:  Reproduced today: search → 502 "(HTTP 429)", chart → 502 "(HTTP 403)". Apple
           throttles or blocks Cloudflare egress addresses. Verified today that
           itunes.apple.com/search, /lookup and /{country}/rss/toppodcasts/.../json all return
           `access-control-allow-origin: *`, so a browser can call them directly from the
           user's own IP — the same path the Android app already uses successfully.
    Fix:   In app.mjs, call Apple directly (keep the 3.1 s client-side spacing, the 2 MiB
           response cap and the existing sanitiser directoryRows — move it into domain.mjs);
           add https://itunes.apple.com to connect-src; keep /api/feed; retire /api/search and
           /api/chart or leave them as a fallback. Update docs/web-app.md privacy text: Apple
           will then see the user's IP as well as the search term and country (it already does
           for Android users). This also removes two Worker invocations per Discover tap.

B2  LOW     FeedParser keeps all episode text in memory; the 64 MiB cap bounds bytes, not heap
    Where: app/src/main/java/com/pod4me/domain/FeedParser.java:18, 49-63, 126-137, 143-152.
    What:  Every item's title/description is retained until parsing ends, then copied into
           ContentValues for SQLite. Measured on the JVM (Latin-1 content, -Xmx256m): a 20.6 MiB
           feed → 33 MiB live heap; 41.2 MiB → 106 MiB; 61.6 MiB → 124 MiB, all in < 200 ms, no
           OOM. Android's ART also stores Latin-1 strings compactly, so Western feeds are fine
           up to the cap. Feeds whose show notes are predominantly non-Latin (Cyrillic, CJK,
           Greek) use two bytes per char and would roughly double these numbers, approaching a
           256 MiB default heap on a 64 MiB feed. Real podcast feeds today top out around
           10–20 MiB.
    Fix:   Cap individual captured fields (e.g. 1 MiB per description, 4 KiB per title, keep
           the head) and/or lower the document cap to the web app's 32 MiB. Do not use
           largeHeap for this.

B3  LOW     Media RSS audio (<media:content>) without <enclosure> is skipped on both platforms
    Where: FeedParser.java:107-111; webapp/public/app/domain.mjs:123-130.
    What:  Publishers that only use <media:content type="audio/..."> get "N episode(s) skipped:
           no supported, valid audio enclosure" and an empty feed. The message is honest, but
           the feed is usable.
    Fix:   Fall back to the first audio <media:content url> when no enclosure is present.

B4  LOW     Web rejects feeds containing "<!DOCTYPE" anywhere, including inside CDATA show notes
    Where: webapp/public/app/domain.mjs:41 (regex over the whole document).
    What:  Show notes that embed an HTML document inside CDATA make the entire feed fail in the
           browser with "XML document types are not supported", while the relay (prefix check,
           worker.mjs:137-157, confirmed by probe) and Android (real DTD only) accept it.
    Fix:   Apply the same preamble-only test as the Worker. DOMParser does not resolve external
           entities, so the risk being guarded against is entity expansion in a real DTD, which
           the preamble check already covers.

B5  LOW     Relay rejects UTF-16 feeds
    Where: webapp/worker.mjs:141 (TextDecoder() defaults to UTF-8 for the preamble check).
    What:  Reproduced with a BOM-prefixed UTF-16LE RSS body: 415 "This address does not contain
           a supported RSS or Atom feed." Android parses the same feed (SAX honours the BOM).
           UTF-16 feeds are rare but exist.
    Fix:   Detect the BOM (FF FE / FE FF) or the charset parameter and decode the preamble with
           that encoding; pass it through to the browser unchanged (it already forwards the
           charset).

B6  LOW     Web: Refresh on an unsubscribed podcast silently re-subscribes it
    Where: webapp/public/app/app.mjs:61 (↻ Refresh shown in every feed view),
           domain.mjs:249 (mergeFeed always sets subscribed: true).
    What:  Open an unsubscribed podcast from an episode, press Refresh: it is subscribed again
           without any confirmation and appears in Podcasts. Refresh-all is correctly limited to
           subscriptions and the busy guard prevents the race with Unsubscribe.
    Fix:   Preserve the previous `subscribed` value in mergeFeed for existing feeds, or replace
           Refresh with "Subscribe" on unsubscribed feed pages.

B7  LOW     Web: the entire library is re-validated and rewritten on every change and every 15 s
            of playback
    Where: webapp/public/app/app.mjs:103, 108-109 (savePosition → persist); storage.mjs:115-125,
           193-262 (validateLibrary over every feed/episode/bookmark, then one IndexedDB put).
    What:  O(library) main-thread work per save: regexes and URL parsing per episode plus a
           structured clone of the whole object. Unnoticeable at a few hundred episodes; at the
           advertised 100,000-episode cap it is seconds per save, every 15 seconds.
    Fix:   Store playback positions/heard flags in a separate small record keyed by episode id,
           or debounce saves and validate only the touched objects (validate fully on
           load/import, which already happens).

B8  LOW     Android ↔ web URL acceptance differs
    Where: domain.mjs:7-19 (safeUrl rejects non-standard ports, dot-less hosts, IP literals);
           FeedParser.httpUrl (accepts them); enclosure type rules differ (FeedParser.java:109
           accepts application/octet-stream and empty type; domain.mjs:128 requires audio/*,
           application/ogg or a known extension).
    What:  A feed list or recommendation produced on Android can contain URLs the web app
           refuses with "Only public HTTP or HTTPS addresses on standard ports are supported",
           and some episodes present on Android are "skipped" on the web.
    Fix:   Document the difference, or relax the web rule for ports on import/share (the relay's
           stricter rule can stay).

B9  LOW     Android: accepting an episode suggestion with "Also subscribe" can create a
            duplicate undated episode
    Where: app/src/main/java/com/pod4me/data/LibraryStore.kt:162-173 (addSharedAudio matches
           only by audio_url; inserts published=0, guid=url); ui/AppModel.kt:150-159.
    What:  When the recipient's copy of the feed uses a different enclosure URL for the same
           episode (tracking prefixes, CDN host changes), the shared episode is inserted as a
           second row in that feed, shown as "Date unknown" at the bottom of Latest, and the
           next refresh cannot merge it.
    Fix:   After subscribing, match on guid or on URL path/filename as well; or keep shared
           downloads in the "shared" pseudo-feed unless an exact match exists.

B10 LOW     Android: a second operation while busy is dropped silently
    Where: ui/AppModel.kt:161-165 (network() returns if busy).
    What:  Most buttons are disabled while busy, but asynchronous entry points are not: a file
           picked for Import/Restore, an accepted incoming share, or Suggest while a long
           refresh runs are ignored with no feedback.
    Fix:   Set a notice ("Please wait for the current operation to finish") instead of
           returning, as the web app does.

B11 LOW     Android: Pod4Me HTTPS links are recognised only with an explicit "/" path
    Where: domain/Suggestions.kt:27 (uri.rawPath == website.rawPath).
    What:  "https://pod4me.aurelien-garivier.workers.dev#feed?url=…" (no slash, a common
           result of retyping or of some link shorteners) falls through to the raw-URL branch
           and the dialog asks whether the Pod4Me site itself is a feed. All links generated by
           Pod4Me/web include the slash.
    Fix:   Accept rawPath "" as equivalent to "/".

B12 LOW     Android: an episode becomes deletion-protected before playback is prepared, and the
            error for a non-audio download suggests the wrong remedy
    Where: data/LibraryStore.kt:306-311 (activate sets activeEpisode); playback/
           PlaybackService.kt:87 (onPlayerError), data/LibraryStore.kt:251-263 (reconcile
           accepts any non-empty file).
    What:  If ExoPlayer fails on the file (e.g. the publisher returned an HTML error page with
           HTTP 200, saved as .audio), the episode stays "current" and undeletable until Stop,
           and the message says "Try downloading this episode again", which will not help.
    Fix:   On onPlayerError clear activeEpisode when nothing is playing; at reconciliation
           sniff the first bytes (ID3/"RIFF"/"OggS"/MP4 "ftyp"/HTML "<") and report
           "The download is not an audio file" instead of storing it.

B13 LOW     Android: the `changing` flag stays raised across a suspension point
    Where: playback/PlaybackService.kt:182-188 (markUnheard sets changing=true, then suspends on
           store.membership).
    What:  Player callbacks during that window (pause, seek) skip their progress save; the
           5-second ticker catches up. Cosmetic; the pattern was noted in the 2026-10-29 audit
           (F13) and is still the only re-entrancy guard.
    Fix:   Narrow the flag to the synchronous seekTo, or use a per-operation token.

B14 LOW     Android: RFC 822 dates with two-digit years or non-English month names → "Date
            unknown"
    Where: FeedParser.java:188-208.
    What:  Such episodes sort last and highlight as undated. Zone names, ISO and date-only
           forms (old F3) are handled.
    Fix:   Add "EEE, d MMM yy HH:mm:ss Z" and try Locale.FRENCH as a second locale, or accept.

B15 INFO    Documented-but-easy-to-miss behaviour differences
    - Web Latest includes episodes of unsubscribed feeds; Android excludes them.
    - Web "4ever" is a metadata marker only; there is no expiry or audio to protect.
    - Web domain.mjs can parse RDF/RSS 1.0, but the relay answers 415 for it (confirmed by
      probe), so neither platform supports RSS 1.0 in practice. Say so once in docs.
    - The relay caches each feed for 5 minutes; a manual Refresh inside that window returns the
      cached XML (documented in web-app.md).

B16 INFO    Scroll-state cache keyed by search text
    Where: ui/PodApp.kt:198-200 ("search:$browseFeed:$searchQuery").
    What:  One LazyListState is created per distinct query string typed in a session and never
           evicted. Negligible memory; mentioned for completeness.
